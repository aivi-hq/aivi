# @aivi/voice

## 0.2.0

### Minor Changes

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`abf44b6`](https://github.com/aivi-hq/aivi/commit/abf44b6b4e2c249b0eebedd3d2f916d3b132dc09) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Quote an addressed meeting sentence to the agent as it was said. The wake phrase was cut out of the sentence first, which could leave a prompt that began with a stray comma, and the phrase is how the agent knows it is being spoken to. Nothing is stripped anymore, and the `stripWake` export is removed.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`68ef412`](https://github.com/aivi-hq/aivi/commit/68ef41242b9c94b3be7989d295f77b60e483645d) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Remove three public members that nothing called: `BatchEngineRun.duration`, `HearingRoom.currentEngineState` and `VoiceTurns.busy`. A room already replays its engine state to every new `onEvent` listener, and a duration is `samples.length / 16000`.

### Patch Changes

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`0727f57`](https://github.com/aivi-hq/aivi/commit/0727f578dc911fee0d954162c142a050a26f7dc5) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Cut a room's turn when the room leaves while its session is still being prepared. The cut only reached a turn that was already asking the model, so a room that left during session creation ran the whole answer for nobody: the slot stayed held and leaving waited until that answer was finished. The turn now ends before the model is asked, and the prepared session is kept for the next join.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`1207465`](https://github.com/aivi-hq/aivi/commit/1207465b44e41e58eaf485fa639773203243b879) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Drop a call-room sentence that is worded after its room closed. An utterance still in the engine when everyone left was batched and armed the finished-window timer on the closed room. That late flush logged `voice.flush` for a prompt that could not be sent, and after a host shutdown it ran against the closed database and threw from a timer. The sentence is now logged as `voice.batch.dropped`, like the rest of a closing batch, and no timer is armed.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`92a9b98`](https://github.com/aivi-hq/aivi/commit/92a9b98e7ddf4840fd1ab1419c2d23bad017a472) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - End a development room's audio source when its engine process dies. The file or microphone capture behind a `voice.room` kept running after an engine crash: nothing stopped it until the host exited, so a microphone stayed open with no engine left to hear it. The source now ends with its engine.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`d984a33`](https://github.com/aivi-hq/aivi/commit/d984a33e85c3f59d95c8a4f8363aa7941cef89f1) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Forget a room's persisted lease id once the restart recovery has returned it. The id stayed in the voice store until that room's next turn, so every later start asked the dispatcher again to release a lease that no longer existed. Capacity was never affected: the dispatcher's own lease was already gone.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`6eb962c`](https://github.com/aivi-hq/aivi/commit/6eb962cd8017ebfa3d48193f0ed78ba406c02cfe) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Guard the engine state a room shows a new watcher. That first event was delivered outside the guard later events get, so a watcher that threw on it threw out of `onEvent`, got no unsubscribe function and stayed registered. It is now logged as `voice.listener.failed` like any other failing watcher.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`ed08d7e`](https://github.com/aivi-hq/aivi/commit/ed08d7eec15aa1ada5db1522df79ece46002964f) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Report a restart-recovered lease as recovered only when its slot came back. When the dispatcher answered that the kill was still unconfirmed, voice logged `turns.recovered` although the slot stayed held. That answer now logs `turns.lease.pending-kill` with the room and pool, like every other release.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`2f6d1ca`](https://github.com/aivi-hq/aivi/commit/2f6d1ca74d7c328e1243ce0440883cb401126194) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Identify the final diarized speaker before committing its line at end of stream. EOF now applies the same completed-stretch binding as a speaker change, so a sufficiently long final utterance no longer loses its speaker name merely because no later activity event arrived.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`8f13509`](https://github.com/aivi-hq/aivi/commit/8f1350958bcdb4db6340081e8f9064d9277f4622) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Note the slot a voice turn holds before its session is prepared. The lease was persisted only after the session had been created, so a crash during that step left a held slot that the next start's recovery did not know about. It is now persisted the moment the slot is granted.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`57566a5`](https://github.com/aivi-hq/aivi/commit/57566a546cb2ba78722244dd7d5cb7d83e459da0) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Close a development room quietly while its own engine still loads. Stopping the room ended the loading process, and that was logged as `voice.engine.start-failed` and shown as engine state `failed`. A closed room no longer reports its own stop as a failed start.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`6d17165`](https://github.com/aivi-hq/aivi/commit/6d171653dc535c84e2fca07b895cd334259d4bb5) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Stop logging `voice.source.exited` when voice ends a development room's decoder itself. Closing a file or microphone room kills its ffmpeg, and that requested exit was warned about as if the source had failed. Only a decoder that ends on its own with a failure is reported now.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`f095845`](https://github.com/aivi-hq/aivi/commit/f095845143bb427a6c7806bf24038426a7f8cb84) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Load a fresh separate speech endpoint after its process dies. A `voice.stt` or `voice.tts` process that exited after loading stayed cached as loaded, so every later utterance was lost and every later answer stayed unspoken until the host restarted. The next request now starts a replacement, as a failed load already did.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`543705a`](https://github.com/aivi-hq/aivi/commit/543705a5c3fedfcfaa9b0306beb18fec4b3f9486) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Speak an answer whose text block opened but whose text never streamed. The `session.text.started` event alone marked the answer as streamed, so when its deltas did not arrive the finished answer was never spoken and nothing was logged. Only text that actually streamed counts now: without any, the whole answer is spoken when it is finished.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`cabe384`](https://github.com/aivi-hq/aivi/commit/cabe384573dd17dd3efa4281b00ca2896528d71f) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Own the shared streaming engine while its models load so shutdown can stop that process immediately. Late readiness and a ready marker followed by process death no longer cache a dead engine. Normal EOF clears the cached engine and diarizer state, and stopped startup attempts do not report a new failure.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`fe507d7`](https://github.com/aivi-hq/aivi/commit/fe507d766e5e236cabc923b0e8c12b6f186356fd) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Stop separate STT and TTS processes during module shutdown even when their models are still loading. The module now owns each process before its ready marker, shares concurrent startup requests, and prevents late readiness or later audio from reviving a stopped endpoint.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`ac8faef`](https://github.com/aivi-hq/aivi/commit/ac8faef8084618772902c7f41a84a094b92f6461) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Check the replies of the separate `voice.stt` and `voice.tts` endpoints the way the streaming engine's are checked. A batch reply whose `text` was not a string was returned as the transcript, and a voice reply with malformed `audio` left its sentence waiting until the timeout while later sentences queued behind it. A malformed reply for a known request now logs a bounded bad-line diagnostic and settles as lost, and a line that is not an object with a request id is reported instead of ignored.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`86731f3`](https://github.com/aivi-hq/aivi/commit/86731f3aab5d59c4649e71740849a607de0d3842) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Validate streaming-engine JSON before delivering events or batch replies. Non-object messages and malformed event fields now produce a bounded diagnostic instead of crashing or manufacturing transcript data. Malformed replies for known requests settle as lost, and an error response cannot certify accompanying text as a successful transcription.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`2a4b15e`](https://github.com/aivi-hq/aivi/commit/2a4b15e703380dac05a3d88970d5ec1f355d7d2f) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Do not interrupt an answer for empty, whitespace or punctuation-only recognition deltas. Mixed audio and linked live lanes now require a letter or digit before barging in. Live lanes also record their first-word latency only when a real word arrives.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`7693bb4`](https://github.com/aivi-hq/aivi/commit/7693bb4566da53db16a1cd408d521744d7ff8fec) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Cut a spoken clause at a punctuation mark only once a space or a line break follows it. A mark at the end of the text received so far was treated as a clause end, so a number that arrived as `3.` and `5` was spoken as two clauses. The mark now waits for the next character, and the closing sentence of an answer is spoken when the answer ends.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`16c8985`](https://github.com/aivi-hq/aivi/commit/16c8985f49996579e5cff392da7e624d2c9c5b8f) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Report live first-word latency in milliseconds. The `voice.lane.firstword` log previously stored rounded seconds in its `ms` field, making sub-second recognition delays appear as zero.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`01044dd`](https://github.com/aivi-hq/aivi/commit/01044dd7c68ce417631ddf75ceedb7e1398843c3) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Stop sending the end-of-answer signal to a mouth after a barge-in. The room contract says `flush` never follows a barge, because `stop` already closed the answer, but a stretch interrupted between two chunks was still flushed.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`13a377a`](https://github.com/aivi-hq/aivi/commit/13a377a543db0ece00fb3d4f8100683a2726b273) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Say when a live utterance is only partly transcribed because the engine died while the person was still speaking. The `voice.lane.partial` warning was logged only when the engine died after the utterance had ended; a death in the middle of it committed the partial line without a word.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`ba0b230`](https://github.com/aivi-hq/aivi/commit/ba0b230b4541fc040b85e0e1ebbdbd170b8a2edf) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Stop the voice setup summary from saying "transcription off". A no to "Download the transcription model now?" only skips the download: the engine block is written either way and the model arrives on first audio. - [#76](https://github.com/aivi-hq/aivi/pull/76) [`7e5c6fe`](https://github.com/aivi-hq/aivi/commit/7e5c6fef3b537173e67119a400204f5263c4cb58) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Answer a request for audio from before the stream began with nothing. `EngineRun.slice` with a negative start returned samples that were not numbers instead of `null`, which would have reached the voiceprint model.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`57cf5b6`](https://github.com/aivi-hq/aivi/commit/57cf5b60e3cb569d009954080303b41c09aac8a0) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Make the reference TTS engine always end a streamed sentence. When the model produced no audio, or stopped without a final chunk, `engine/mlx-tts.py` sent nothing, so the client waited out its whole timeout while later sentences queued behind it. The engine now sends a final reply without audio in that case.

- [#76](https://github.com/aivi-hq/aivi/pull/76) [`3531412`](https://github.com/aivi-hq/aivi/commit/3531412229f0803fff0dfb0461d42b40e5091903) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - Keep a typographic closing quote with the spoken sentence it closes.
