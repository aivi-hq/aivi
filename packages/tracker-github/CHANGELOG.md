# @aivi/tracker-github

## 1.0.0

### Major Changes

- [#67](https://github.com/aivi-hq/aivi/pull/67) [`ef850e4`](https://github.com/aivi-hq/aivi/commit/ef850e45c30be394d168f2a971aa0a6849764f29) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - **One pool set: `dispatcher.pools` is now the only capacity system.**
  `scheduler.resources`, `scheduler.maxConcurrent` and the per-module
  `resource` names are retired — jobs, channel turns, ticket work and voice
  rooms all draw the same named pools, and `scheduler` keeps job *timing*
  defaults only. Plugin blocks rename `resource` to `pool`; a block that
  names a pool must name one that exists, and while no pools are configured
  capacity is unmoderated and any name is idle. `poolCapacities(dispatcher)`
  is the one reading point the scheduler and both channel engines claim
  through. `AiviServices` grows two seats: `voice` (the voice plugin's
  adapter, empty until `@aivi/voice` provides one) and `dispatcher` (ticket
  capacity, now visible to modules).

- [#67](https://github.com/aivi-hq/aivi/pull/67) [`ef850e4`](https://github.com/aivi-hq/aivi/commit/ef850e45c30be394d168f2a971aa0a6849764f29) Thanks [@RWOverdijk](https://github.com/RWOverdijk)! - **The board answers in types, not `any`.** The GraphQL node shapes
  (project V2 boards, fields, options, items, issues) are declared once in
  the client and shared with setup-project, which reads the same board —
  the looseness stays in the query documents, the mapping code speaks
  types. `pool` names replace `resource` on the tracker's own block, and
  the module claims capacity through `poolCapacities` like every other
  service.
