What it does

The parts that keep an assistant useful after the first week.

A chat window forgets the work around it. aivi keeps the documents, the schedule, and the state of each job in one server, so an answer can point at a source and a ticket can survive a restart.

01

Search across the work you already have

One index for docs, decisions, memories and past conversations. Keyword search works from the first boot, and semantic search arrives after the local models are warmed.

02

Answer in the chat you use

Discord and Slack, in DMs and threads. Each conversation keeps its own OpenCode session, and commands cover search, jobs, model choice, and stopping a running turn.

03

Take work from a board

Linear and GitHub Projects. Lanes decide which agent works a ticket and when a person takes over. The board stays the source of truth.

04

Work in its own checkout

A ticket can run in its own git worktree on the branch the tracker names. Stop it and the local work goes away, while anything pushed stays.

05

Keep a schedule

Recurring and one-off jobs, with results sent to a chat channel or back into a session. An occurrence missed during downtime is recorded, not silently skipped.

06

Remember, then tidy up

A nightly dreaming pass turns conversations into dated facts, moves superseded notes to an archive, and proposes rules and skills for a person to approve.

07

Use a browser with your logins

A persistent Chrome profile for unattended work. Each session gets its own tabs, and the logins survive restarts.

08

Stay inside its capacity

When pools are configured, one set of model slots is shared by chat, jobs, tickets and dreaming. Extra work waits in a queue instead of competing for the same machine.

The boundary

OpenCode is the runtime. aivi is the shift around it.

OpenCode still owns sessions, message history, models, providers, tools, skills and permissions. aivi does not wrap or replace any of that. It runs a server that keeps those sessions reachable from the rest of your day: an index over the knowledge, a scheduler for jobs, adapters for chat and trackers, and a place for memory to settle.

The agents stay ordinary OpenCode agents. You can open the same home in OpenCode, switch models, read a transcript, or do the work by hand. Nothing about aivi makes that harder.

Get started

One install, then one command.

You need Node 26.12 or newer and a macOS or Linux machine that can stay awake. Setup creates the server, seeds the agents into the OpenCode home, and signs this machine in. It can install the server as a background service before it finishes.

  1. Install the CLI and run setup. It asks whether this machine creates a server or connects to one.
  2. Take the background service if the machine stays on. Otherwise run aivi serve in a terminal.
  3. Add a project or a chat channel when you are ready. The getting started guide covers both.

Search runs locally. Your documents stay in their own directories, and the index lives in the aivi home.

Open the getting started guide 
# install the command line
npm i -g @aivi/cli

# create the server or sign in to one
aivi setup

# keep it running in the foreground
aivi serve

Setup can install the same server as a background service, so this last line becomes optional.
